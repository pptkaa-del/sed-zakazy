# Управление предприятием

Веб-приложение для заказов, контрагентов и оплаты счетов:

- **Заказы** — список по статусам («Планируется», «В работе», «Закрыт») с поиском. Идентификатор заказа присваивается автоматически, его можно изменить; отдельное поле «Номер заказа» — для заказов по рамочным договорам. Заказчик выбирается из выпадающего списка контрагентов, который фильтруется при вводе; нового заказчика система добавит в контрагенты сама. В заказе: комментарии, документы по заказу (файлы любого формата), строки для закупки (наименование, количество, поставщик или «в наличии», № счёта) со вставкой из Excel, счета поставщиков, задачи план-графика, номер выставленного заказчику счёта.
- **Контрагенты** — заказчики, поставщики и подрядчики: сайт, несколько контактов (контактное лицо, телефон, почта), загруженные договоры, заказы контрагента и комментарии.
- **Бухгалтерия** — счета к оплате, сгруппированные по заказам, сумма к оплате, отметка оплаты с номером платёжки и чеком. Кнопка «Скачать все счета к оплате» отдаёт ZIP-архив: файлы счетов по папкам заказов и реестр в CSV.
- **План-график** — закупки и работы на диаграмме по заказам: свои люди и бригады подрядчиков на задаче, загрузка по дням.

Сервер написан на Node.js (версия 16 или новее, рекомендуется 20+) и не требует npm-пакетов. Данные хранятся в папке данных. По умолчанию это `~/sed-zakazy-data` в домашней папке пользователя, вне папки сайта, а в Docker — том `/data`:

| Что | Файл |
|---|---|
| Проекты, заказы, счета, задачи | `db.json` |
| Пользователи (пароли в виде хэшей scrypt) | `users.json` |
| Загруженные файлы | `files/` |
| Ключ подписи сеансов (создаётся сам) | `secret.key` |

Резервная копия — это копия папки данных целиком.

**Первый вход.** Пока пользователей нет, сайт при открытии предлагает создать администратора. Сделайте это сразу после запуска. Остальных сотрудников администратор добавляет кнопкой «Пользователи» в шапке. Консоль для этого не нужна.

## Роли

| Роль | Код | Что может |
|---|---|---|
| Администратор | `admin` | всё |
| Менеджер | `manager` | заказы, контрагенты, документы, строки для закупки, счета, план-график; оплату не отмечает |
| Бухгалтер | `accountant` | видит всё, отмечает оплату, прикладывает чеки |
| Сотрудник | `user` | видит всё, загружает счета в заказы, правит и удаляет свои неоплаченные счета |
| Просмотр | `viewer` | только просмотр |

Права проверяет сервер, а не только интерфейс.

**Отметка о скачивании.** Когда бухгалтер открывает или скачивает файл счёта, сервер запоминает время. Менеджеры и сотрудники видят у счёта «✓ скачан» с датой, в карточке счёта — кто и когда скачал. У бухгалтера нескачанные счета выделены, для них есть фильтр «Не скачанные». Если к счёту приложить новый файл, отметка сбрасывается.

**Пользователи.** Администратор управляет сотрудниками на вкладке «Пользователи»: добавить, изменить имя, логин, роль или пароль, заблокировать, удалить. Там же видно время последнего входа. Блокировка сразу завершает все сеансы сотрудника.

## Установка одной командой

Скрипт `install.sh` сам определяет, где он запущен, и делает всё нужное. Повторный запуск той же команды обновляет приложение, данные при этом не трогаются. Репозиторий публичный, токен не нужен.

**Свой сервер на Ubuntu, без домена и сертификата (по IP-адресу):**

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/sed-zakazy/main/install.sh | sudo bash
```

Сайт откроется по адресу `http://IP-сервера`, скрипт покажет его в конце. Что делает скрипт:

- ставит Node.js в `/opt/node`;
- скачивает код в `/opt/sed-zakazy`;
- кладёт данные в `/var/lib/sed-zakazy`;
- создаёт службу systemd `sed-zakazy`, которая запускается вместе с сервером;
- ставит nginx на порт 80 и отключает его стандартную страницу;
- открывает порт в брандмауэре ufw, если тот включён.

Если порт 80 занят другим сайтом:

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/sed-zakazy/main/install.sh | sudo bash -s -- --port 8080
```

Без HTTPS пароли передаются по сети открытым текстом. Это допустимо во внутренней сети компании, но не в интернете.

**Свой сервер с доменом и HTTPS (Ubuntu, Debian, CentOS, AlmaLinux и т. п.):**

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/sed-zakazy/main/install.sh | sudo bash -s -- ваш-домен.ru --email ваша@почта.ru
```

То же самое, плюс сертификат Let's Encrypt и переадресация на HTTPS. A-запись домена должна заранее указывать на сервер.

**Виртуальный хостинг (reg.ru и похожие), по SSH, без sudo:**

```bash
curl -fsSL https://raw.githubusercontent.com/pptkaa-del/sed-zakazy/main/install.sh | bash -s -- ваш-домен.ru
```

Скрипт поставит Node.js в `~/node` (версию подберёт под сервер), скачает код в `~/sed-zakazy` и подключит его к сайту через Passenger. Затем проверит, что сайт отвечает, и при работающем HTTPS включит защищённую cookie. Домен уже должен быть добавлен в панели хостинга.

**Обновление:**

```bash
sudo bash /opt/sed-zakazy/install.sh
```

На своём сервере — эта команда (с доменом и `--port` добавьте их в конце, как при установке). На виртуальном хостинге — `bash ~/sed-zakazy/install.sh ваш-домен.ru`.

**Управление службой на своём сервере:**

```bash
sudo systemctl status sed-zakazy      # состояние
sudo journalctl -u sed-zakazy -f      # журнал
sudo systemctl restart sed-zakazy     # перезапуск
```

Ниже — ручная установка по шагам, если нужно понять или поправить, что делает скрипт.

## Получение кода

Код лежит в репозитории GitHub. На сервере его удобнее всего забрать через `git`, тогда обновление — это одна команда `git pull`.

```bash
git clone https://github.com/pptkaa-del/sed-zakazy.git sed-zakazy
```

Без git можно скачать ZIP: на странице репозитория Code → Download ZIP. Распакуйте его и переименуйте папку в `sed-zakazy`.

## Вариант 1. Хостинг с ispmanager 6

Нужна панель ispmanager 6 (lite, pro или host) с поддержкой Node.js. Это VPS с панелью или хостинг, где в настройках сайта можно выбрать обработчик Node.js. На обычном PHP-хостинге без Node.js приложение не запустится.

Названия пунктов меню ниже могут немного отличаться в разных версиях панели.

1. **Включите Node.js.** Под администратором панели: «Настройки → Конфигурация ПО» (или «Программное обеспечение»), установите Node.js. Нужна версия 20 или новее.
2. **Разрешите Node.js пользователю.** «Пользователи → (ваш пользователь) → Изменить» → отметьте право на Node.js. Если отдельной галочки нет, пропустите шаг.
3. **Создайте сайт.** «Сайты → Создать сайт»:
   - имя — ваш домен, например `sed.example.ru`;
   - обработчик — **Node.js**, версия 20 или 22;
   - способ подключения — **Порт** (подходит и «Сокет»);
   - команда запуска — `node server.js`;
   - сразу отметьте «Защищённое соединение (SSL)» и выпустите сертификат Let's Encrypt, а также «Перенаправлять HTTP-запросы в HTTPS».
4. **Загрузите файлы.** «Менеджер файлов» → откройте папку сайта (обычно `www/sed.example.ru`) → загрузите `sed-zakazy.zip` → «Извлечь». Файлы `server.js`, `package.json` и папка `public` должны оказаться прямо в папке сайта, а не во вложенной `sed-zakazy/`. Если извлеклись во вложенную, перенесите их на уровень выше.
5. **Настройте приложение (рекомендуется).** Скопируйте `sed.env.example` в `sed.env` и раскомментируйте строку `COOKIE_SECURE=1`, раз сайт работает по HTTPS.
6. **Перезапустите проект.** «Сайты → (ваш сайт) → Перезапустить». `npm install` не нужен: внешних пакетов нет.
7. **Создайте администратора.** Откройте `https://sed.example.ru` и заполните форму «Создайте учётную запись администратора». Затем через кнопку «Пользователи» добавьте менеджеров и бухгалтера.

**Порт или сокет.** Сервер сам берёт порт или путь к сокету из переменной окружения `PORT` (также понимает `SOCKET` и `APP_SOCKET`), которую задаёт панель. Если сайт отвечает ошибкой 502, посмотрите в настройках сайта, какой порт или сокет назначен, и впишите его в `sed.env` строкой `PORT=…`. Затем перезапустите проект.

**Если что-то не работает:**

| Признак | Что проверить |
|---|---|
| 502 Bad Gateway | Приложение не запустилось или слушает не тот порт. Смотрите журнал сайта в панели, в `sed.env` укажите `PORT` из настроек сайта |
| Вход не срабатывает, форма просто обновляется | `COOKIE_SECURE=1` при открытии сайта по `http://`. Откройте по `https://` или уберите строку |
| Большие файлы не загружаются (ошибка 413) | В настройках сайта увеличьте «Максимальный размер тела запроса» (nginx `client_max_body_size`) до 55 МБ |
| Где лежат данные | `/var/www/ПОЛЬЗОВАТЕЛЬ/sed-zakazy-data` (домашняя папка пользователя сайта). Сохраняйте её в резервных копиях |

Консольные команды (`node server.js users` и другие) можно выполнять из «Shell-клиента» панели, если он включён. Для обычной работы они не нужны.

## Вариант 2. Виртуальный хостинг reg.ru через SSH

На виртуальном хостинге reg.ru Node.js-приложения запускает Apache через модуль Passenger, а подключаются они в `.htaccess` сайта. Сервер сам перезапускает приложение и поднимает его после сбоев. Держать процесс через `nohup` или `pm2` не нужно.

1. **Включите SSH.** Личный кабинет reg.ru → «Хостинг» → ваша услуга → «Доступ по SSH» → включить. Там же видны логин (вида `u1234567`) и адрес сервера.
2. **Добавьте домен** в панели хостинга (ISPmanager → «Сайты», или «WWW-домены»), если его ещё нет. Выпустите бесплатный SSL-сертификат.
3. **Подключитесь:**

   ```bash
   ssh u1234567@адрес-сервера
   ```

4. **Установите Node.js в домашнюю папку.** Права администратора не нужны. nvm на reg.ru не подходит: на серверах старая версия `sed`, и скрипт nvm падает с ошибкой.

   Узнайте версию glibc:

   ```bash
   ldd --version | head -1
   ```

   Если число в конце 2.28 или больше, ставьте Node.js 20:

   ```bash
   cd ~ && curl -fLO https://nodejs.org/dist/v20.18.1/node-v20.18.1-linux-x64.tar.xz && tar xf node-v20.18.1-linux-x64.tar.xz && mv node-v20.18.1-linux-x64 node && rm node-v20.18.1-linux-x64.tar.xz
   ```

   Если меньше (например, 2.17), ставьте Node.js 16:

   ```bash
   cd ~ && curl -fLO https://nodejs.org/dist/v16.20.2/node-v16.20.2-linux-x64.tar.xz && tar xf node-v16.20.2-linux-x64.tar.xz && mv node-v16.20.2-linux-x64 node && rm node-v16.20.2-linux-x64.tar.xz
   ```

   Добавьте Node.js в путь и проверьте:

   ```bash
   echo 'export PATH="$HOME/node/bin:$PATH"' >> ~/.bashrc
   grep -q bashrc ~/.bash_profile 2>/dev/null || echo '[ -f ~/.bashrc ] && . ~/.bashrc' >> ~/.bash_profile
   source ~/.bashrc && node -v
   ```

   Если вместо версии reg.ru пишет «необходимы права суперпользователя», значит, команда не найдена: проверьте `ls ~/node/bin` и строку `PATH` в `~/.bashrc`.

5. **Получите код в домашнюю папку**, не в папку сайта:

   ```bash
   cd ~ && git clone https://github.com/pptkaa-del/sed-zakazy.git sed-zakazy
   ```

   Или загрузите и распакуйте ZIP через файловый менеджер панели (см. «Получение кода»). Итог должен быть один: `~/sed-zakazy/server.js`.

   Узнайте точное имя папки сайта:

   ```bash
   ls ~/www
   ```

6. **Запустите настройку**, подставив свой домен:

   ```bash
   bash ~/sed-zakazy/deploy/regru-setup.sh sed.example.ru
   ```

   Скрипт пропишет Passenger в `~/www/sed.example.ru/.htaccess` (прежний сохранит как `.bak`), переименует заглушку `index.html`, создаст папку данных `~/sed-zakazy-data` и файл настроек `~/sed-zakazy/sed.env`.
7. **Откройте `https://sed.example.ru`** и создайте администратора. Сделайте это сразу.
8. **Включите защищённую cookie:** в `~/sed-zakazy/sed.env` раскомментируйте `COOKIE_SECURE=1` и перезапустите приложение:

   ```bash
   touch ~/sed-zakazy/tmp/restart.txt
   ```

**Обновление версии:**

```bash
cd ~/sed-zakazy && git pull && touch tmp/restart.txt
```

Данные в `~/sed-zakazy-data` и настройки в `sed.env` при обновлении не затрагиваются.

**Если что-то не работает:**

| Признак | Что проверить |
|---|---|
| Открывается старая страница или список файлов | В папке сайта остался `index.html` или `index.php`. Переименуйте его и проверьте, что `.htaccess` содержит строки `Passenger…` |
| Ошибка 500 сразу после настройки | Тариф не поддерживает Passenger или директивы в `.htaccess`. Уточните в поддержке reg.ru, доступен ли Node.js на вашем тарифе |
| Страница ошибки Passenger «Web application could not be started» | Текст ошибки на этой странице и в журнале ошибок сайта (панель → «Журналы»). Частая причина — неверный путь в `PassengerNodejs` после смены версии Node.js; запустите скрипт настройки повторно |
| Вход не срабатывает | Включён `COOKIE_SECURE=1`, а сайт открыт по `http://`. Откройте по `https://` |
| Нужна консольная команда | `cd ~/sed-zakazy && node server.js users`. Файл `sed.env` читается автоматически |
| `source ~/.bashrc` выдаёт ошибку `sed: … незавершенное адресное регулярное выражение` | В `~/.bashrc` остались строки nvm. Удалите их и папку `~/.nvm`, оставьте только строку с `PATH` |

Резервная копия: `tar czf ~/sed-backup-$(date +%F).tar.gz -C ~ sed-zakazy-data`.

Хостинг может запускать несколько копий приложения одновременно. Сервер это учитывает: каждая копия перечитывает данные, если их изменила другая.

## Вариант 3. Docker

Нужны Docker с Compose и nginx на сервере.

1. Получите код и запустите:

   ```bash
   sudo git clone https://github.com/pptkaa-del/sed-zakazy.git /opt/sed-zakazy && sudo chown -R $USER /opt/sed-zakazy
   cd /opt/sed-zakazy
   mkdir -p data && sudo chown 1000:1000 data
   docker compose up -d --build
   ```

   Контейнер работает от непривилегированного пользователя с UID 1000, поэтому папке `data` нужен этот владелец.

2. Откройте сайт и создайте администратора в форме первого входа. Можно и из консоли (пароль спросит интерактивно):

   ```bash
   docker compose exec app node server.js useradd admin admin "Иванов И. И."
   ```

3. Подключите домен через nginx (см. раздел «Домен и HTTPS»).

Обновление: `cd /opt/sed-zakazy && git pull && docker compose up -d --build`.

Приложение слушает только `127.0.0.1:3000`, снаружи к нему ходят через nginx.

## Вариант 4. VPS без панели (systemd)

Нужен Node.js 16 или новее (рекомендуется 20+).

```bash
sudo useradd --system --home /opt/sed-zakazy sed
sudo git clone https://github.com/pptkaa-del/sed-zakazy.git /opt/sed-zakazy
sudo mkdir -p /opt/sed-zakazy/data && sudo chown -R sed:sed /opt/sed-zakazy/data
sudo cp deploy/sed-zakazy.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now sed-zakazy
```

Затем настройте nginx (раздел ниже), откройте сайт и создайте администратора.

Обновление: `cd /opt/sed-zakazy && sudo git pull && sudo systemctl restart sed-zakazy`.

## Домен и HTTPS

1. В DNS направьте A-запись домена (например `sed.example.ru`) на IP сервера.
2. Скопируйте `deploy/nginx.conf` в `/etc/nginx/sites-available/`, замените `sed.example.ru` на свой домен и включите сайт:

   ```bash
   sudo ln -s /etc/nginx/sites-available/sed.example.ru /etc/nginx/sites-enabled/
   ```

3. Получите сертификат Let's Encrypt:

   ```bash
   sudo certbot --nginx -d sed.example.ru
   ```

4. Проверьте конфиг и перезапустите nginx:

   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

Если сайт временно работает без HTTPS, уберите `COOKIE_SECURE=1` из `docker-compose.yml` или из файла службы, иначе вход не сработает.

## Управление пользователями

В Docker добавляйте перед командой `docker compose exec app`.

```text
node server.js useradd <логин> <роль> "<Имя>" [пароль]   создать
node server.js passwd  <логин> [пароль]                   сменить пароль (завершает все сеансы)
node server.js userdel <логин>                            удалить
node server.js unblock <логин>                            снять блокировку
node server.js users                                      список
node server.js backup  [файл.json]                        выгрузить записи в JSON
```

Пользователь может сменить свой пароль сам: кнопка «Пароль» в шапке. Администратор управляет сотрудниками через кнопку «Пользователи»: добавить, сменить роль, задать новый пароль, удалить.

## Настройки

Задаются переменными окружения или в файле `sed.env` рядом с `server.js` (образец — `sed.env.example`). Переменные окружения важнее файла.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт или путь к Unix-сокету (также `SOCKET`, `APP_SOCKET`) |
| `HOST` | `0.0.0.0` | адрес; для systemd задан `127.0.0.1` |
| `DATA_DIR` | `~/sed-zakazy-data` | папка данных |
| `MAX_FILE_MB` | `50` | предельный размер файла (поправьте и `client_max_body_size` в nginx) |
| `SESSION_DAYS` | `14` | срок жизни входа |
| `COOKIE_SECURE` | — | `1` — cookie только по HTTPS |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `ADMIN_NAME` | — | создать администратора при первом запуске, если пользователей нет |

## Резервное копирование

Ежедневная копия через cron:

```bash
0 3 * * * tar czf /backup/sed-$(date +\%F).tar.gz -C /opt/sed-zakazy data
```
